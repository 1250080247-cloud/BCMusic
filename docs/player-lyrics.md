# Player and lyrics contract

The Now Playing view follows the supplied references: full-screen cover-derived background, artwork and existing playback controls on the left, readable lyrics on the right; mobile stacks the same content. The underlying YouTube/SoundCloud player stays mounted. Existing next/previous, repeat, seek, favorites and volume continue to use the current media controller and stores. Escape and the close control return to the application without stopping playback.

`GET /api/lyrics?title=…&artist=…&duration=…` is a read-only public lookup against LRCLIB, then lyrics.ovh when necessary. Title and artist are limited to 250 characters; duration is optional, finite and between 0 and 86400 seconds. Missing/invalid metadata returns 400. Success returns `{status, source, plainLyrics, lines}`, where status is `synced`, `plain`, `instrumental` or `unavailable`, and source is `LRCLIB`, `lyrics.ovh` or null. Each timed line contains `{time, text}` in seconds. Temporary upstream failures return 503 with a generic error; playback continues independently. Existing response fields and callers are preserved.

The lookup strips bracketed and trailing presentation labels such as “Official Video” while preserving cover/remix/live versions. Featured credits (`ft.`, `feat.`) are separated from the title and retained in the artist list. Responses must match the normalized track and the complete set of credited artists, whether LRCLIB places featured credits in the title or the artist field. A solo recording, a different collaborator or a remix is not accepted as the original collaboration. Timed lyrics require a known playback duration matching the recording within 3 seconds; otherwise only plain lyrics are shown. No synthetic word/syllable timing is generated. Standard LRC timestamps and repeated timestamps are supported. Clicking a timed line seeks the current recording. Follow mode scrolls only the lyrics region and pauses when the listener manually scrolls; reduced-motion preferences disable smooth scrolling.

LRCLIB lookup makes at most two requests: a direct lookup (3-second timeout), then a search (separate 3.5-second timeout) when the direct lookup fails transiently or has no complete synchronized result. Search uses the base title and lead artist to discover spelling/credit layouts; the complete credits are still checked before accepting a result. Explicit HTTP 4xx rejection/rate limiting stops further LRCLIB requests. A usable direct result remains available if the search fails. Plain lyrics do not prevent searching LRCLIB for a matching synchronized version.

Usable LRCLIB lyrics, including plain text and instrumental results, take priority and never trigger the backup. When LRCLIB is unavailable or has no usable lyrics, one `GET https://api.lyrics.ovh/v1/{artist}/{title}` request is allowed, with a separate 3-second timeout. Full collaboration credits and version labels are kept in individually encoded path segments. Both providers are free public endpoints without API keys. Only song title/artist metadata is sent to the backup; application cookies, account data and credentials are not forwarded.

lyrics.ovh returns plain text without independent artist/version/duration metadata or verified timestamps. Its output is always `plain` with an empty `lines` array; its text is never parsed into fabricated timing. The player displays the source and its static-lyrics caption. Coverage and matching depend on the provider; this does not guarantee lyrics for every remix or recording. Both providers reporting no result returns HTTP 200 `unavailable`; a provider outage without a usable result remains HTTP 503 and can be retried. No useful LRCLIB response is replaced with a backup error.

The shared transport permits only the two fixed HTTPS origins, forbids redirects and caps response bodies at 512000 bytes while reading the stream. Accepted lyric text remains limited to 80000 characters. UI source links use a fixed allowlist and lyrics are rendered as text. Fetch-cache entries retain the existing one-hour revalidation; final successful API responses retain the existing five-minute public cache policy. Total configured provider timeouts are at most 9.5 seconds, with no automatic retry loop or added dependency.

Opening/changing a song cancels old lyric requests and never displays an older song's response. Existing plain lyrics remain a fallback. Loading, unavailable, instrumental and temporary-error states are explicit. The active provider is attributed in the lyrics view. Lyrics are not written into MongoDB, existing schemas or listening-history records.

Verification: `npm test`, `npm run lint`, `npm run build`, read-only MongoDB ping/API checks and desktop/mobile browser checks including reduced motion. The dependency audit remains part of verification.

Completed verification and the distinction between real provider requests and controlled UI fixtures are documented in [verification-2026-10-28.md](verification-2026-10-28.md). YouTube playback errors stop the playing indicator and display a message for the affected recording. Closing the full-screen view restores keyboard focus to its opener and leaves the media controller mounted.

The backup provider and expanded playlist verification are recorded in [playlist-and-lyrics-fallback.md](playlist-and-lyrics-fallback.md). Provider contract: [lyrics.ovh API specification](https://github.com/NTag/lyrics.ovh/blob/main/apiary.apib).
